# Локальный стенд HTTP, DNS и TLS от XNova

Это небольшое приложение для практики сетевой диагностики. Оно слушает только
`127.0.0.1`; для упражнений не нужны Docker, системные права или интернет после
установки пакетов. Нужны Python 3.12 и, для команд с `curl`, установленный curl.

Создайте свой репозиторий из публичной заготовки курса. Работайте в собственной
копии: добавьте `client.py` и `tests/test_diagnostics.py`, фиксируйте наблюдения
и исправления там.

## Запуск

В macOS или Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
.venv/bin/python -m lab serve
```

В PowerShell на Windows:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe -m lab serve
```

В другом терминале выполните `curl --noproxy "*" -i
http://127.0.0.1:8765/health`. Ожидается HTTP 200 и `{"status":"ok"}`.
Остановите сервер `Ctrl+C`. Если порт занят, выберите свободный
непривилегированный номер: `python -m lab serve --port 8767` из активного
окружения, затем используйте этот же порт в запросах.

Проверить исходный стенд: `python -m pytest -q`. Проверки открывают реальные
loopback-соединения, включая HTTP и HTTPS; они не требуют внешней сети.

## Маршруты и локальный TLS

`/health` и `/items/42` возвращают 200. Неизвестный путь возвращает 404,
`/unavailable` — HTTP 503, `/redirect` — 302 с `Location: /health`.
`/slow?delay=0.5` задерживает ответ на указанное число секунд от 0 до 2.

Для HTTPS создайте одноразовый локальный CA и сертификат, затем запустите тот же
сервер на другом порту:

```sh
python -m lab certs --output .lab-certs
python -m lab serve --port 8766 --tls-dir .lab-certs
curl --noproxy "*" --resolve localhost:8766:127.0.0.1 --cacert .lab-certs/ca.pem -i https://localhost:8766/health
```

На Windows используйте `.venv\Scripts\python.exe` вместо `python`, если
окружение не активировано. Каталог `.lab-certs` игнорируется Git. Его закрытый
ключ не показывайте и не загружайте. При необходимости удалите каталог и
создайте новую пару. `--cacert` доверяет CA только для этого вызова curl;
системное хранилище сертификатов менять не требуется.

## Самостоятельные случаи

В `cases/case-01.json` … `case-05.json` лежат пять отдельных исходных запросов.
Содержимое каждого файла — URL и ограничение ожидания ответа. Метки
`{http_port}`, `{https_port}`, `{alternate_port}` подставляются из вашего
локального запуска; последний порт должен быть проверен как порт без listener.
Каждый случай начинается с неуспеха. Определите этап сбоя, сохраните улику,
измените минимум в **одном** конфиге или своём клиенте и повторите ту же
проверку до HTTP 200. Перед следующим случаем верните исходный конфиг.

Для `case-01` используйте `lab.resolver.controlled_ipv4(hostname)` **только как
явную учебную модель системного разрешения имени**. Она разрешает локальные
имена и вызывает `socket.gaierror` для остальных. Это не сетевой DNS-запрос.
Обычный `socket.getaddrinfo("localhost", ...)` также не доказывает, что был
обмен с DNS-сервером. Для всех случаев соединение направляйте на IPv4
`127.0.0.1`, сохраняя исходное имя для HTTP Host и TLS SNI/проверки сертификата.
В HTTPX отключайте proxy-настройки среды через `trust_env=False`; в curl
используйте `--noproxy "*"`. Не выключайте проверку TLS.
